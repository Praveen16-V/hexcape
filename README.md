# Hexcape

Carve a path through a hex field you can only edit near yourself, guiding a dog
that never stops walking toward her dinner.

A Flutter/Flame puzzle game for Android. Tap a hex near the dog to clear it and
she drifts toward whatever opens up; tap out of her reach and nothing happens.
Cleared tiles grow back, so the route you opened is closing while you open the
next one.

## Running it

```bash
flutter pub get
flutter run
```

Requires the Flutter SDK on the stable channel (built against 3.44.9, Dart
3.12.2) and an Android SDK. There is no iOS, web or desktop target — `android/`
is the only platform folder, and the game is portrait-locked and built for one
thumb.

## Layout

| Path | What lives there |
|---|---|
| `lib/game/` | Rules, progression, entitlements, billing, tuning |
| `lib/hex/` | Hex grid maths and coordinates |
| `lib/systems/` | Simulation: drift, regrowth, hunger, patrols |
| `lib/entities/` | The dog, the bone, obstacles, powerups |
| `lib/components/` | Flame render components |
| `lib/ui/` | Flutter overlays: map, HUD, sheets, paywall |
| `lib/l10n/strings.dart` | Every user-facing string, in one file |
| `tool/` | Asset generation — audio, icon, pet sprite sheets |
| `docs/` | Design notes, plus the published site (privacy policy) |

`assets/audio/` is generated by `tool/generate_audio.dart` and the launcher icon
by `tool/render_icon.dart`. Both are build artefacts, not hand-made files —
re-run the script rather than editing the output.

## Tests

```bash
flutter test
```

Around fifty test files. Two are worth knowing about because they encode release
rules rather than behaviour:

- `test/shipping_test.dart` — the Android shell. Asserts the launcher icon is
  ours at every density, the launch window is the game's dark rather than white,
  the app is labelled Hexcape, release signing reads a real keystore, and the
  keystore is never committed.
- `test/settings_test.dart` — among other things, that the developer panel is
  unreachable from a player's settings sheet. It opens the paid campaign, so
  this one is guarding revenue.

The developer panel is reached by tapping the **SETTINGS** title seven times.
It is deliberately available in release builds, because every playtest of this
project is one.

## Structure of the game

A hundred levels across six bands — Tutorial, Foundation, Pressure, Mastery,
Collapse, Vigil — then Endless, which has no final level. Levels 1–20 are free,
along with one free run at level 21. The rest unlock with a single non-consumable
purchase, `hexcape.full`, implemented in `lib/game/store.dart`.

There is no backend. No network calls, no analytics, no ads, no accounts. All
state is local `shared_preferences`. The only thing that talks to the outside
world is Google Play Billing.

## Releasing

See `docs/store-listing.md` for the Play listing copy and asset checklist, and
the comment at the top of `android/app/build.gradle.kts` for keystore setup.

```bash
flutter build appbundle --release
```

If `android/key.properties` is missing, gradle warns and signs with the debug
keystore — which Play rejects at upload. Check the build log for that warning
before uploading anything.
